# Documentation Index

This repository uses `docs/` as the canonical home for project documentation.

## Sections

- [architecture/README.md](./architecture/README.md): runtime model, permissions, messaging, storage, privacy, release architecture.
- [product/README.md](./product/README.md): product scope, user value, and use-case-level docs.
- [setup/README.md](./setup/README.md): local development, configuration, debugging, troubleshooting.
- [features/README.md](./features/README.md): feature inventory and implementation plans.
- [api/README.md](./api/README.md): runtime message contracts, storage schema, and command contracts.
- [quality/README.md](./quality/README.md): test strategy, compatibility, and manual QA checklists.
- [security/README.md](./security/README.md): threat model, secure-development rules, privacy disclosure alignment.
- [operations/README.md](./operations/README.md): release runbooks, store submission notes, support operations.
- [contributing/README.md](./contributing/README.md): workflow, documentation standards, and definition of done.
- [adr/README.md](./adr/README.md): architecture decision records.
- [templates/README.md](./templates/README.md): reusable documentation templates.
- [archive/README.md](./archive/README.md): historical or high-volume docs kept out of default navigation flow.

## Ownership And Maintenance

- Treat `docs/` as a source-of-truth surface, not an afterthought.
- When behavior changes, update the related docs in the same PR.
- Prefer one canonical doc per topic.
- Keep links relative and public-safe.
